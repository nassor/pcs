## What it does

Plain S3 over any S3-compatible endpoint: AWS, MinIO, R2, Ceph RGW, RustFS. The byte format comes
from the transformer the node's required `transformer` key names, so this crate reads no byte's
meaning.

A source lists its prefix once and drains the objects in key order, streaming each one into an
unnamed tempfile that a reader thread decodes off the executor. EOF is the listing exhausted; there
is no re-list or tail mode.

A sink accumulates encoded rows in an in-memory buffer and uploads them as one object when a flush
threshold fires: enough rows, enough encoded bytes, or enough wall-clock time since the object took
its first batch. Every key is `{prefix}/{YYYYMMDDTHHMMSS.mmmZ}-{NNNNNN}{suffix}`, so a listing
replays objects in the order they were written.

## In service config

<div class="code">
<div class="code-cap"><span>KDL</span><em>the transformer node, the source and the sink, all inside one workflow</em></div>

```kdl
transformer "orders_csv" format="csv" {
    options has_headers=#false
}

source "orders_in" type="S3Source" component="Order" transformer="orders_csv" {
    config prefix="incoming/orders" {
        connection {
            bucket "${PCS_S3_BUCKET:-pcs-orders}"
            endpoint "${PCS_S3_ENDPOINT:-http://127.0.0.1:9000}"
            access_key_id "${PCS_S3_ACCESS_KEY:-rustfsadmin}"
            secret_access_key "${PCS_S3_SECRET_KEY:-rustfsadmin}"
            allow_http #true
        }
        schema_fields "id" type="Int64" nullable=#false
        schema_fields "amount" type="Float64"
        schema_fields "status" type="Utf8"
    }
}

sink "orders_out" type="S3Sink" component="Order" transformer="orders_csv" {
    config prefix="processed/orders" suffix=".csv" {
        flush max_rows=50000 max_bytes=134217728 max_age_ms=60000
        connection {
            bucket "${PCS_S3_BUCKET:-pcs-orders}"
            endpoint "${PCS_S3_ENDPOINT:-http://127.0.0.1:9000}"
            access_key_id "${PCS_S3_ACCESS_KEY:-rustfsadmin}"
            secret_access_key "${PCS_S3_SECRET_KEY:-rustfsadmin}"
            allow_http #true
        }
        schema_fields "id" type="Int64" nullable=#false
        schema_fields "amount" type="Float64"
        schema_fields "status" type="Utf8"
    }
}
```

</div>

## Config keys

Both halves take a shared `connection` node and `schema_fields`. The sink adds `prefix`, `suffix`
and `flush`; the source adds `prefix` and `schema_from`.

| Key | Type | Default | Required |
|---|---|---|---|
| `connection` | node | | yes, on both halves |
| `connection.bucket` | string | | yes; the bucket must already exist, `object_store` has no creation API |
| `connection.endpoint` | string | the AWS endpoint for `region` | no |
| `connection.region` | string | `us-east-1` | no |
| `connection.access_key_id` | string | none | no |
| `connection.secret_access_key` | string | none | no |
| `connection.session_token` | string | none | no |
| `connection.allow_http` | bool | `#false` | no; `#true` for a local server over plain HTTP |
| `connection.virtual_hosted_style` | bool | `#false` | no; path style is what a bare host or IP needs |
| `connection.skip_signature` | bool | `#false` | no; unsigned requests for a public bucket |
| `connection.from_env` | bool | `#false` | no; seed the client from the `AWS_*` environment first, which is how the IMDS, ECS, EKS and web-identity credential paths are reached |
| `connection.options` | table | empty | no; every remaining `object_store` S3 or HTTP-client option by its own name, an unrecognised key is an error |
| `prefix` | string | `""` | no; a byte prefix handed to the service's list API, so name it with a trailing slash to stay inside one directory |
| `suffix` | string | `""` | sink only; appended to the generated key, nothing is inferred |
| `flush.max_rows` | integer | `100000` | sink only; `0` disables |
| `flush.max_bytes` | integer | `134217728` | sink only; `0` disables, the open object lives in memory |
| `flush.max_age_ms` | integer | `60000` | sink only; `0` disables, driven by the sink's own ticker task |
| `schema_from` | `"config"` or `"object"` | `"config"` | source only |
| `schema_fields` | list of fields | none | yes, on both halves |

`flush` is checked after each `write_batch` for rows and bytes, and by the ticker for age, so
whichever fires first closes the object. All three at `0` means exactly one object, at `finish`,
which is what a `one_shot` batch job usually wants.

## Schema and format

A source hands the format either the declared `schema_fields` (`schema_from "config"`, the default)
or nothing, letting the format read its own schema out of the object (`schema_from "object"`). In
the second mode the object's schema must equal `schema_fields` field for field, and the mismatch is
a configuration error naming both schemas. [csv](@/transformers/csv.md) and
[ndjson](@/transformers/ndjson.md) want `config`; [parquet](@/transformers/parquet.md) and
[avro](@/transformers/avro.md) reject a declared schema outright and want `object`. A sink always
needs `schema_fields`, whatever the transformer, because that is the schema the rows are written
with.

## Sharp edge: the open object lives in the sink's memory

<div class="note note-warn">
<span class="note-label">Sharp edge</span>
<p>
A sink holds the open object in memory until a flush threshold fires or <code>finish</code> runs. A
process killed mid-object loses those rows, while the source it drained has already advanced, so the
rows never come back. Size the flush thresholds to how much loss a restart is allowed to cause.
</p>
</div>

## Errors you can hit

| Message | Raised by |
|---|---|
| `S3Source config: {e}` / `S3Sink config: {e}` | the factory, when the config node fails to deserialize |
| `S3Source moves bytes and needs a 'transformer' key naming a declared transformer` | the shared context, when the node declared none |
| `S3Source: unknown connection option '{key}': {e}` | `build_store`, for an unrecognised `options` key |
| `S3Source: listing {prefix}: {e}` | the first `next_batch`, listing the prefix |
| `S3Source: object '{location}' carries schema [...] but the config declared [...]` | `next_batch`, a `schema_from "object"` mismatch |
| `S3Sink: write_batch called after finish` | writing to a finished sink |
| `S3Sink: put {key}: {e}` | a flush upload that the server refused |
